# Подробное руководство

Короткое описание проекта — в [README](../README.md). Здесь то, что нужно уже
в работе: как поднять первое подключение, чем режимы отличаются друг от друга,
чего на Windows сделать нельзя и как приложение дружит с Android-клиентом.

## Где что лежит

Приложение ничего не пишет рядом с собой — все данные в профиле пользователя:

| Что | Где |
|---|---|
| Профили, настройки, кэш | `%APPDATA%\FreeTurn\` |
| Журналы | `%APPDATA%\FreeTurn\logs\` |
| Ядро и его предыдущая версия | `%LOCALAPPDATA%\FreeTurn\core\` |
| Компонент адаптера (wintun.dll) | `%LOCALAPPDATA%\FreeTurn\bin\` |
| Рабочий каталог WebView2 | `%LOCALAPPDATA%\FreeTurn\webview2\` |

## Быстрый старт

1. **Поднимите сервер.** Либо вручную по
   [quickstart ядра](https://github.com/samosvalishe/free-turn-proxy/blob/master/docs/quickstart.md),
   либо прямо из приложения: вкладка **«Сервер»** → доступ по SSH → «Установить
   ядро» → «Запустить» → «Настроить WireGuard и забрать конфиг».
2. **Создайте звонок VK Calls** (`https://vk.ru/call/join/...`) и **не завершайте
   его** — по нему клиент получает TURN-данные. Ссылка уникальна для каждого
   клиента и в share-ссылки не входит.
3. **Заполните профиль**: адрес сервера, ссылку на звонок и ключ обфускации.
   Проще нажать на вкладке «Сервер» кнопку «Забрать параметры подключения» —
   сервер сам сообщит режим, профиль и ключ.
4. **Подключитесь** большой кнопкой на вкладке «Главная».
5. Выберите режим **VPN** в профиле — туннель поднимется сам.

## Режимы работы

### VPN — встроенный туннель (по умолчанию для VPN)

Приложение само поднимает туннель WireGuard/AmneziaWG: создаёт сетевой адаптер,
настраивает адреса, маршруты, DNS и MTU. Ставить клиент WireGuard не нужно —
как и в Android-версии, всё делает одно приложение.

Что нужно: вставить в профиль конфигурацию, которую выдал сервер
(«Дополнительно» → WireGuard), выбрать режим **«VPN — встроенный туннель
WireGuard»** и нажать «Подключить». Приложение само:

- подставит `Endpoint` — локальный сокет ядра (по умолчанию `127.0.0.1:9000`);
- опустит `MTU` до **1280** — поверх DTLS, TURN, UDP и IP стандартные 1420
  фрагментируются и теряются;
- посчитает `AllowedIPs` по правилам раздельного туннелирования;
- добавит `PersistentKeepalive = 25` — через TURN-релей молчащий пир быстро
  теряет привязку канала;
- сохранит параметры обфускации AmneziaWG (`Jc`, `S1`, `H1`, `I1`…) — они едут
  в туннель как есть.

Конфигурацию клиента **выдаёт сервер** — так же, как в Android-версии. Ключи,
адрес в туннеле, свой публичный ключ и параметры обфускации AmneziaWG он
генерирует сам, обмениваться ключами вручную не нужно:

- **«Запросить у сервера»** в профиле — заводит пира и кладёт готовый конфиг
  в профиль (нужен доступ по SSH на вкладке «Сервер»).
- **«Настроить WireGuard и забрать конфиг»** на вкладке «Сервер» — первичная
  настройка. Приложение само выбирает сценарий: если на сервере уже работает
  обычный WireGuard, оно добавляет вас пиром в существующий интерфейс, а если
  WireGuard нет — поднимает AmneziaWG (при необходимости доставив на сервер
  пакет `wireguard-tools`, без которого install.sh не может создать ключи).
- **«Заготовка вручную»** — запасной путь для сервера, поднятого не через это
  приложение: приложение создаст пару ключей и заполнит всё, кроме публичного
  ключа сервера. Свой публичный ключ вы передаёте владельцу сервера.

### Прокси

Ядро просто слушает локальный порт и релеит то, что в него пришло. Трафик
системы при этом **не заворачивается** — режим нужен, когда клиент указывают
вручную: Xray, sing-box или сторонний WireGuard. Для последнего в профиле есть
кнопка «Сохранить .conf» — файл уже содержит правильные `Endpoint` и `MTU`:

```ini
[Peer]
Endpoint            = 127.0.0.1:9000
AllowedIPs          = 0.0.0.0/0
PersistentKeepalive = 25
```

> **Порядок запуска для стороннего клиента:** сначала «Подключить» в FreeTurn,
> потом туннель в WireGuard. Встроенного туннеля это не касается — он поднимается
> сам после того, как ядро займёт свой сокет.

## Ограничения

Честный список того, чего на Windows сделать нельзя или можно лишь частично.

- **Раздельное туннелирование — по подсетям, а не по приложениям.** Аналога
  Android `VpnService` в Windows нет; выбор приложений потребовал бы драйвера WFP.
  Реализовано через расчёт `AllowedIPs`: «всё, кроме указанных подсетей» или
  «только указанные подсети».
- **Счётчики трафика доступны только в режиме VPN.** Ядро объём трафика не
  публикует (счётчики его внутреннего API доступны лишь мобильной сборке), поэтому
  цифры берутся у самого туннеля. В режиме прокси их взять неоткуда, и вместо
  нулей приложение честно пишет, что счётчиков нет.
- **Трафик ядра идёт мимо туннеля по маршрутам, а не по процессу.** В Android
  сокеты ядра исключает из VPN сам `VpnService.protect()`; в Windows такого
  механизма нет, поэтому приложение пиннит на физический шлюз адреса, без
  которых ядро не работает: его DNS-серверы и узлы авторизации VK (сами
  TURN-серверы пиннит ядро флагом `-routes`). Туннель поднимается только после
  того, как ядро установит канал через TURN. Если провайдер выдаст VK новые
  адреса при уже поднятом туннеле, обновление TURN-учёток может не пройти —
  тогда достаточно переподключиться.
- **Туннель поднимает приложение, а не ядро.** У консольного клиента ядра
  встроенного туннеля нет (он есть только в мобильной сборке), поэтому GUI
  использует тот же amneziawg-go и адаптер Wintun самостоятельно.
- **IPv6 в туннеле не ведётся:** серверная часть раздаёт IPv4, адреса и маршруты
  IPv6 из конфигурации пропускаются.
- **Версия ядра определяется по первой строке его журнала** (`-version` у клиента
  нет): приложение коротко запускает бинарь и читает `Free Turn Proxy client
  version=...`.
- **Аварийное завершение.** При `taskkill /F` ядро гибнет вместе с приложением
  (job-объект Windows), но снять свои маршруты уже не успевает. Штатный выход
  через «Выход» в трее чистит всё корректно.

## Совместимость с Android-клиентом

- **Ссылки `freeturn://`** совпадают с форматом ядра байт в байт (проверено
  golden-вектором, снятым с `internal/uri` ядра). Поддержано и расширение
  Android-клиента — поле `vk` со ссылкой на звонок.
- **Бэкап** — формат v4: конверт `PBKDF2-HMAC-SHA256` (210 000 итераций) +
  `AES-256-GCM`, внутри профили в раскладке `ServerJson`. Файлы читаются в обе
  стороны.
- **Расхождения**: поля, специфичные для Android (`splitTunnelApps` с именами
  пакетов, `useCarrierDns`, `syncServerSwitches` и настройки внешнего вида), на
  Windows не применяются, но переносятся без потерь — круг Android → Windows →
  Android ничего не теряет. Свои поля (`routes`, `magicPort`,
  `splitTunnelSubnets`, `subUrl`) приложение пишет под собственными ключами;
  Android незнакомые ключи игнорирует. Поле `platform` при импорте всегда
  становится `desktop`.

## Безопасность

- Ключи обфускации, пароли SSH и sudo хранятся зашифрованными через **DPAPI** с
  привязкой к приложению, а не открытым текстом в JSON.
- **Отпечаток ключа SSH-сервера** подтверждается при первом подключении и потом
  проверяется: смена ключа — явная ошибка, а не молчаливое доверие.
- Ключ обфускации маскируется в журнале — он же попадает в скриншоты.
- Токен GitHub (необязательный, для лимита запросов) хранится в настройках
  приложения.

## Сборка из исходников

```bash
# Требуется Go 1.25+ и Node.js 20+
cd frontend && npm ci && npm run build && cd ..
go install github.com/tc-hib/go-winres@v0.3.3
go-winres make --in winres/winres.json --arch amd64 --out rsrc
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -tags desktop,production \
  -ldflags "-s -w -H windowsgui -X main.version=0.1.0" -o build/bin/FreeTurn.exe .
```

Проверки:

```bash
GOOS=windows go vet -tags desktop,production ./...
GOOS=windows golangci-lint run --build-tags desktop,production ./...
go test ./...
```

Сборку под Linux проект поддерживает только ради тестов: боевая цель одна — Windows.

## Как поделиться профилем

Кнопка «Поделиться» в меню профиля собирает ссылку `freeturn://` и показывает её
**QR-кодом** — как в Android-клиенте: получателю достаточно навести камеру.
Ссылку можно скопировать, сохранить текстом, а сам код — картинкой PNG.
Гостевая ссылка на вкладке «Сервер» показывается так же.

Код строится для ссылок до 1200 символов (предел взят у Android-клиента):
за этой длиной картинка получается настолько плотной, что телефон её уже не
читает, и приложение честно предлагает передать ссылку текстом.

> Ссылка профиля несёт ключ обфускации сервера, а гостевая — ещё и
> конфигурацию WireGuard, выданную этому гостю, вместе с его приватным ключом.
> Своя конфигурация в ссылку профиля не попадает. Показывайте код только тому,
> кому доверяете: сфотографировать экран может кто угодно.
