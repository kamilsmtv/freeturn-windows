# План: FreeTurn для Windows

## Стек — остаёмся на предложенном

Go 1.23 + **Wails v2** + React 18 + TypeScript + Tailwind. Один `FreeTurn.exe`
(~12 МБ), рантайм не нужен, WebView2 проверяем при старте и предлагаем
установку Evergreen-бутстраппера. Причины остаться: ядро на Go — переиспользуем
`internal/uri`-совместимый код и криптографию бэкапа без FFI; трей, DPAPI,
IP Helper и Job Objects доступны через `golang.org/x/sys/windows`.

Лицензия: **GPL-3.0** — берём формат конфигов и бэкапа Android-клиента, а часть
логики (парсер control-ответов, нормализация WG-конфига) фактически повторяет
их решения. Дешевле и честнее сразу GPL, чем спорить о границе.

## Структура

```
cmd/freeturn/          main + манифест requireAdministrator + иконка (rsrc)
internal/
  core/      менеджер процесса ядра: запуск, args, чтение stdout, стоп, Job Object
  updater/   GitHub API (ETag+кэш), сравнение версий, скачивание, sha256, откат
  profile/   модель Server/ClientConfig/ServerOpts, стор в %APPDATA%
  link/      freeturn:// парсер и билдер (+ поле vk), совместимый с ядром
  sub/       подписки: fetch, парсинг, расписание
  backup/    PBKDF2-210k + AES-256-GCM, формат v4 Android
  secrets/   DPAPI для obf-key/паролей SSH
  routes/    добавление/снятие маршрутов, счётчики адаптера (GetIfTable2)
  vps/       SSH-клиент + RPC v2 поверх install.sh ядра
  errs/      маппинг сообщений ядра в русские тексты
  tray/      трей, автозапуск, single instance
frontend/    React + TS + Tailwind
docs/        analysis.md, plan.md
.github/workflows/release.yml
```

Данные: профили и логи `%APPDATA%\FreeTurn\`, ядро и его предыдущая версия —
`%LOCALAPPDATA%\FreeTurn\core\{client.exe, client.prev.exe, meta.json}`.
Рядом с .exe не пишем ничего.

## Этапы (после каждого — сборка и отчёт, что проверить руками)

1. **Скелет.** Wails-проект, манифест админ-прав, проверка WebView2, каркас UI
   (список профилей / детали / настройки / лог), тема по системной.
2. **Ядро + апдейтер.** Сборка аргументов по образцу `ClientArgs` + `-routes`,
   запуск в Job Object (падение GUI = смерть ядра), потоковый лог,
   версия из первой строки, GitHub-релизы с ETag, sha256 по `checksums.txt`,
   атомарная замена, откат, первый запуск без ядра.
3. **Профили и обмен.** CRUD + клонирование, `freeturn://` импорт/экспорт,
   подписки с ручным и плановым обновлением, бэкап/восстановление v4, DPAPI.
4. **UI целиком.** Основные поля + «Дополнительно» (KCP, DNS, TURN-override,
   platform, obf-timing), индикатор, счётчики, лог с фильтром/копированием/экспортом,
   генератор WG-конфига (`Endpoint 127.0.0.1:9000`, `MTU 1280`).
5. **Интеграция с Windows.** Трей и меню, свернуть-в-трей, автозапуск,
   автоподключение, корректная уборка маршрутов при выходе и при `taskkill`.
6. **VPS по SSH.** `probe/install/wg-setup/start/logs/...` поверх install.sh ядра,
   живой лог, разбор ответа в новый профиль (peer, obf-key, client-id, WG-conf).
7. **Тесты и CI.** Unit: парсинг/сборка `freeturn://`, сборка аргументов,
   сравнение версий, апдейтер на моке GitHub API, крипта бэкапа (вектор из
   Android-формата). `go vet` + `golangci-lint` + release workflow на теге.

## Вопросы, на которые нужен твой ответ

1. **Версия ядра.** Флага `-version` нет; читаем первую строку лога
   `Free Turn Proxy client version=...`. Согласен? (альтернатива — держать
   версию только из тега релиза и не сверять с бинарём).
2. **Счётчики трафика.** В proxy-режиме честного источника нет (раздел 6
   analysis.md). Показывать «н/д» или считать по WG-адаптеру только в VPN-режиме?
3. **Раздельное туннелирование** — только по подсетям/маршрутам. Ок?
4. **Лицензия GPL-3.0** для проекта — подтверждаешь?
5. **VPS**: используем `install.sh` ядра (HBL), а не GPL-bundle Android. Ок?

Жду подтверждения плана — дальше начинаю с этапа 1.
